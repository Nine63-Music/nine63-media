# NINE63 MUSIC — Beat Store

A static, data-driven beat-selling site built for **963 Beats**. Vanilla JavaScript, no framework, no build step. Drop an MP3 in a folder, run one command, and the whole catalog updates.

Modern streaming-style UI: pure black + layered grays with a lime accent, persistent audio player, queue, favorites, filtering, licensing tiers, and an honest order-request cart.

## Quick start

```powershell
# 1. Serve the site (any static server works; dev server ships in-repo)
node tools/serve.js 8080

# 2. Open it
# http://localhost:8080/
```

## Adding a beat

1. Drop the MP3 into a collection folder under `Beats/` (create a new folder to make a new collection).
2. Put artwork in that folder's `images/` subfolder if you want it (optional — a generated SVG cover is used otherwise).
3. Regenerate:

```powershell
node tools/generate-catalog.mjs
```

The generator:

- Reads real ID3v2 tags for **BPM, key, year, and Serato play count** — nothing is faked. Beats without a key simply omit the pill.
- Infers **genres** from the folder name (split on ` x `) and **moods** from a `FOLDER_META` table in the tool.
- Parses titles like `963 Beats - GLOW - 150BPM - Supertrap Type` down to `GLOW`.
- Matches `images/` artwork (filename or hash), falls back to embedded `APIC` art, then to a generated SVG.
- Merges `data/overrides.json` last.

## Manual corrections — data/overrides.json

The catalog is auto-generated, but every human touchpoint lives in `data/overrides.json` (optional file; safe to delete). Keyed by exact beat **title** or **source file path**:

```json
{
  "producer": "963 Beats",
  "beats": {
    "GLOW": {
      "genres": ["Supertrap", "Darkology"],
      "moods": ["Dark", "Cinematic"],
      "key": "Fm",
      "description": "A menacing supertrap banger..."
    }
  },
  "descriptions": {
    "OTHER TITLE": "Short blurb shown on the beat's detail page."
  },
  "featured": ["GLOW"]
}
```

- `beats.<key>` — partial beat object; any field overrides the generated one. `genres`/`moods` accept display names and are slugified.
- `descriptions.<title>` — detail-page blurb.
- `featured` — array of titles to force onto the home "Fresh drops" row. If empty, the generator defaults to the top-3 played per collection.

After editing: `node tools/generate-catalog.mjs` again.

## Pricing & copy

Everything editorial lives in `assets/js/config.js`:

- `licenses` — four tiers (Basic $30 / Premium $60 / Unlimited $120 / Exclusive $500). Edit names, prices, features, `popular` flag.
- `copy` — hero, section headings, empty states.
- `marquee` — the ticker under the hero.

## How licensing works (honest cart)

The cart builds an **order request** — it asks for an email and produces a copyable summary, then invites you to email it in. The "Email this to us" button opens a pre-filled message to the store inbox (set via `contactEmail` in `assets/js/config.js` — kept out of the page markup on purpose). It never fakes a payment or a download. A real payment integration slots into the same code path (see the `place-order` handler in `assets/js/pages.js`).

## SEO

- Per-route `<title>` / `<meta name="description">` + Open Graph tags are set by the router (`assets/js/router.js`).
- Each beat detail page injects `application/ld+json` (`MusicRecording` + `Offer`) structured data.
- Generate a `sitemap.xml` with:

```powershell
node tools/sitemap.mjs https://your-domain.com
```

## Tests

Requires Chrome and the dev server running:

```powershell
node tools/serve.js 8080        # terminal 1
node tools/smoke-test.cjs       # terminal 2 — 41 checks, exit code 0 = green
```

The smoke suite drives the site headlessly: renders every route, plays audio, filters, adds to cart, exercises the order flow, opens the mobile drawer, and asserts no console errors. Re-run it after any change.

## Deploying

Pure static files with hash routing (no server rewrites needed). Serve over HTTPS for audio + autoplay reliability. Sitemap + SEO meta live in the generated files, so a plain static deploy is fully crawlable.

**This project is ~413MB (mostly the MP3s), but the free Vercel tier caps uploads at 100MB.** The repo is wired to split the deploy:

1. **Media on the free jsDelivr CDN.** Push `Beats/` to a public GitHub repo with `tools/deploy-media.mjs` (uses the GitHub API — no git install needed):
   ```powershell
   $env:GH_TOKEN = "ghp_xxx"   # PAT with `repo` scope
   node tools/deploy-media.mjs your-username nine63-media --create
   ```
   It prints the CDN base URL. Put it in `data/site.js`:
   ```js
   window.ACLASS_SITE = { assetBase: "https://cdn.jsdelivr.net/gh/your-username/nine63-media@latest" };
   ```
   Both audio and artwork resolve through `Utils.assetUrl`, so a single line switches the whole media layer. Keep `assetBase` empty (`""`) for local dev.

2. **Shell to Vercel (free).** `.vercelignore` excludes `Beats/` and `tools/`, keeping the upload ~1MB and under the 100MB cap:
   ```powershell
   npm i -g vercel
   vercel login
   vercel --prod --yes --name nine63-music
   ```
   The site then lives at `https://nine63-music.vercel.app`.

If you use a host without the 100MB cap (e.g. Cloudflare Pages) you can ignore all of this — just upload the whole folder. When you add beats later: regenerate the catalog, re-run the media deployer, then re-deploy the shell.
